## Findings (most severe first)

1. **Major: the end is said once, for 6 seconds, and leaves no mark.** Where: `lib/client.js`, `FocusButton` (in the done phase the label is "Focus timer", the tooltip "Focus timer", no dot) and `Banner` (`holdMs` 6000). What: after the toast goes, nothing outside the panel says a timer ended (`footer-done-light.png`). With the chime off, the sound down, or no click in the window since its last reload (no AudioContext then), an owner who looked at another window for 6 seconds misses the end, and the footer looks exactly as it does before any timer. For a timer the end is the feature. Fix: a done mark on the footer button (a success-coloured dot or check, label and tooltip "Focus session done at 10:25 AM") kept until the panel is opened or the next timer starts; consider an opt-in system notification for an end while the window is hidden, and a longer hold for a focus end.
2. **Major: a hidden window says the end while hidden, not later.** Where: `lib/client.js` `tick()` and `take()`; README "Said when it ends" ("A window that was hidden at the end says it later, with the time it ended … without the chime"). What: `tick()` sends `complete` at zero whatever the visibility, and `take()` toasts and chimes at once; only the 5-second read checks visibility. With the window hidden I saw the toast and the chime fire at the end and nothing said when it was shown again. A minimized DSH window reports hidden (and Chromium on macOS also marks a fully covered window hidden), so this is an everyday case; the README's promise holds only when the window did not know the timer was running. Fix: when `!visible()`, keep the announcement pending (a chime at the end is still useful) and say it on the change to visible, with its time; test it with a hidden `visibilityState` in `test/focus.test.js` and the e2e. Or, at the least, make the README say what happens.
3. **Minor: in DSH's narrow rail, Focus's footer button pushes Wallpaper's partly out of view.** Where: the `sidebar.footer.action` entry (order 91) in DSH's folded rail (windows under 1024 px). What: DSH lays footer actions in one row; with Focus off Wallpaper's button shows 32 of 32 px, with Focus on 22 of 32, and Focus's own shows 22 of 32 with its running dot mostly in the hidden part (`window-760-light.png`, `window-760-focus-off-light.png`). DESIGN.md: never hide another plugin's UI, and "prove you coexist" with a neighbour's footer button on, off and on. The README mentions only Focus's own button. Fix: Focus cannot rearrange DSH's rail, but it can give the panel a second door that works there (an item in DSH's More menu or a keyboard shortcut), add an e2e check at 760 px with Wallpaper on that clicks the button and measures the neighbour, say in the README that Wallpaper's button is cut too, and raise the rail's one-row footer as an open question for DSH.
4. **Minor: the done state shows the finished timer's length.** Where: `FocusPanel`, `fmtTime(rem)` in the ring. What: after a focus ends, the big clock shows the old length (25:00, or 0:10 in my test) with a full ring, while the main button offers "Start short break" at 5 minutes (`panel-done-light.png`). Fix: in the done state show the next step's length, or "Done", in the ring.
5. **Minor: a raw home path where people read.** Where: `checkConfig` problem text shown at the bottom of the panel. What: "… Focus keeps its timer in /Users/…/focus." (`panel-problem-light.png`); DESIGN.md section 9 says no raw paths in the window. Fix: in the window say "in its default folder (focus in DSH's data folder)"; keep the full path in `focus.log` and DSH's log.
6. **Minor: the custom field's only visible label is a faint placeholder.** Where: `data-focus-custom` input. What: the three length fields have visible labels; the custom field shows only DSH's light-grey placeholder "Custom" (its name comes from `aria-label`). Fix: a visible label, as the length fields have.
7. **Nit: Reset beside Pause throws a running session away at once.** No undo or confirmation; the log keeps it. Consider "Undo" in a toast after a Reset of a running focus session.
8. **Nit (docs):** "next to Settings": the app's DSH 0.2.1-rc.3 footer item is "More". Rollback says "load the 0.1.0 folder" without saying where it is (commit 5c0d8da, `plugins/focus`); give the command.
9. **Nit (log):** `resume` does not log the new end (`resume focus at 1493s left`), while `start` does. Add `ends <time>`.
10. **Nit (tests):** "nothing plays on page load" is not asserted (the e2e's stand-in counts notes, not AudioContexts made before a click); the 760 px pictures reuse an open panel, so no check clicks the footer button in the rail.

## What would make it a 9.5

- An end the owner cannot miss: a done mark on the footer button until it is seen, and the hidden-window path made true (said on return, with its time), each with a unit test and an e2e check.
- In the narrow rail, a way to the panel that does not cut Wallpaper's button, measured in the e2e with Wallpaper on, off and on.
- The done state's clock, the window's problem note without a raw path, and a visible label on the custom field.
- The README fixed where it is wrong (hidden window, the rail, Settings or More, where 0.1.0 is).
