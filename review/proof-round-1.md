## Findings (most severe first: blocker, major, minor, nit; each with where, what, and the fix)

1. **Major: a fix claim with a fault word in it is never read, so it is never flagged.** Where: `plugins/proof/lib/claims.js`, `NEGATED` (line 108), used at line 362. What: any clause holding fail, failing, broken, error, red, pending and the like is taken for a failure report, even when the word is only the object of a success verb. Live, "Fixed the failing test in parse.js." after "Fix the failing test in parse.js.", with nothing run and the test still failing, made no claim and no card. Through Proof's projection the same holds for "The failing test now passes.", "I fixed the broken import." and "Fixed the error in parse.js."; "The fix is in and verified." is not read either. These are among the commonest things a coding agent says, and exactly what Proof is for. Fix: negate only when the fault word is the predicate ("3 tests still fail", "the build is broken", "it errors on …"), not when a success verb governs it ("fixed the failing …", "the failing test now passes", "no longer errors"); add these shapes to the corpus.
2. **Major: a question or a "Do not" reads as a request for new work, so an honest summary is flagged.** Where: `plugins/proof/lib/evidence.js`, `asksForWork` (line 1323): `do` is in its verb list and matches at the start of a sentence. What: live, after a turn whose `npm test` passed 4 of 4, "Do the tests pass? Answer in one short sentence, without running anything again." answered "Yes, all 4 tests passed." got a card telling the person they asked for new work; the independent check then VERIFIED the claim and said Proof had misread the request. Through the projection, "OK. Do the tests pass?" and "Do not run anything, just summarize." do the same, while "Did the tests pass?" and "Don't run anything; summarize …" stay quiet. Fix: do not count `do` as a work verb when it is an auxiliary (before `not`/`n't`, or before a subject in a question), never read a sentence ending in `?` as work, and add such follow-ups to the corpus.
3. **Major: on fresh text one honest claim-making turn in seven is flagged, and three in forty are called contradicted.** Where: `lib/evidence.js` (count matching) and the README's *How well it reads*. What: on the never-tuned hold-out, 6 of the 40 honest turns are flagged (15%); the README's 10.0% divides by 60 because it counts the 20 turns that claim nothing, and its 10% floor is met that way. Three get the red "This turn's own output says otherwise" from a number read as the test total: "30 back-to-back runs of the file: 30/30 passed" against the suite's 48; dbt's "PASS=9 … (4 models, 5 tests …)"; "cargo test still passes" against a filtered run of 2 when the claim names 31. A false "contradicted" accuses the agent of lying, which costs more trust than a missed flag. Fix: call a count a contradiction only when both numbers count the same thing (the whole run's tests, the same runner, after the last change), otherwise *no evidence* at most; report false flags over claim-making turns too, with a floor for false contradictions.
4. **Minor: a verified claim keeps its flag.** Where: `lib/client.js` (`FlagCard`, `flagHead`) and the counts in `lib/ledger.js`/`page.js`. What: after the check answered VERIFIED, the card still opens with the amber "Proof · Nothing in this turn shows this", the ledger still counts "1 with no evidence" and the header "3 claims flagged". Fix: once a check verifies a claim, head the card "Verified by an independent check" (or fold it) and count it apart.
5. **Minor: a stopped check names the wrong limit.** Where: `lib/verifier.js` `arm` (the reason uses `this.minutes()` when it fires). What: the first check was armed for 20 minutes, stopped after 20, and says "It took longer than 30 minutes" in *Independent checks*, *What happened* and the check thread's note, because I had changed the setting to 30 meanwhile; inside the check thread the note also says "Open the check to see how far it got". Fix: keep the minutes a check was given on the check and use them; drop "Open the check" from the note in the check itself.
6. **Minor: things are said twice.** Where: `lib/client.js` (`checkLine`, `FlagCard`, `ClaimRow`, `ChecksCard`, `HistoryCard`) and the reasons in `lib/verifier.js`. What: "could not check" then "Could not check: Not checked: the independent check was switched off."; "checking" then "Checking in a read-only thread on …"; a contradicted claim's why and its *What the turn shows* give the same run; the header's sentence on how checks run is the checks card's subtitle again; each *What happened* entry names its session in the heading and again in its line. DESIGN.md: one state per card, say each thing once. Fix: the tag carries the state and the line only the reason; drop *What the turn shows* when it repeats the why.
7. **Minor: raw words where people read.** Where: the whys in `lib/evidence.js`, drawn by `lib/client.js`. What: commands keep their Markdown backticks (`` `git push origin main` exited 1``), the provider shows as its id "owner-ascents" where DSH's own model menu says "Owner Gateway (DSH Test)", the restart reason says "(interrupted)", and the form asks for the provider and model as free text. Fix: draw inline code as code, name the provider as DSH does, say "DSH restarted while it ran", and offer DSH's model list in the form.
8. **Minor: a running check does not say what it checks, and the threads crowd the session list.** Where: `lib/verifier.js` (the question goes in as a host message, which DSH does not draw) and `CheckNote` (drawn after the turn ends). What: opening a running check shows DSH's "Plugin status updated" and the model's work but no question and no note until it ends; three "Proof check · …" threads took half of `calc`'s rows in the sidebar. Fix: draw the note on the check's first turn while it runs; consider grouping or archiving finished check threads.
9. **Minor: a session opened while Proof is off drops off its page after it is back on.** Where: the page reads its sessions from DSH's list rows (`sessionRows` in `lib/ledger.js`). What: with `enabled: false` I opened the session with two claims; after turning Proof back on and restarting, *Sessions with claims* listed 2 sessions instead of 3 and *Independent checks* called it "a session", until I opened it again (its card was fine). The README says nothing is lost when Proof is off. Fix: on start, fold the claims of rows that lack Proof's view (or ask DSH to), or say so under Limits.
10. **Minor: focus drops to the page after *Check it*.** Where: `lib/client.js` `FlagCard`. What: the button is replaced by the check's line and focus falls to the document body (also for *Check again*); a keyboard user starts again from the top. Fix: move focus to the new line or to *Open the check*.
11. **Minor: Copy is logged as a file export.** Where: `lib/remote.js` `exportLedger` (Copy uses it). What: *What happened* says "Ledger exported as Markdown … as proof-ledger-….md" for a Copy, naming a file that was never saved. Fix: log "Ledger copied as Markdown".
12. **Nit: lists out of order and out of line.** *Independent checks* is ordered by when each started (or, if it never did, was asked) but shows when it ended ("1 h ago" above "43 min ago"); its time column has no fixed width, so rows start at different places. The kind after a claim's time ("Turn 1 · 2 min ago · passed") sits beside a *no evidence* tag and reads like a verdict.
13. **Nit: README and window differ in small ways.** The checks card offers *Open Proof's settings* only when there are no checks (the README says whenever the check is off); the restart paragraph does not say that DSH ends a cut check's turn, so it settles as unclear at once; the rollback tag `proof-v1.0.0` does not exist yet; the false-flag denominator (Finding 3).
14. **Nit: the check thread runs at the model's default effort, and 5 minutes was far too short today.** Where: `lib/verifier.js` (the model choice has no effort). What: the check's requests carried no effort (DSH's "Default"), where the profile's sessions run at Low; on the owner gateway this afternoon the first check was still working at 20 minutes and the second needed 24, so the default 5 would have stopped both. Fix: ask for low effort, and say in the README and the form's help what a check needs on a busy gateway.
