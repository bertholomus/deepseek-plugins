## Findings (most severe first: blocker, major, minor, nit; each with where, what, and the fix)

1. **Major: everyday coding requests get notes on two common words.** Where: the fit rule in `lib/search.js` (two shared words, any words) with the terms of `lib/text.js`, and the measured sets in `test/fixtures/canon/relevance/`. What: a note fits when it shares any two words with the prompt, however common: "Write a small Python function that checks whether a string is a palindrome…" gets the mascot note ("small", "files") and Home.md ("write", "checks"); "Set up a GitHub Actions workflow that runs the tests on every push." in `~/work/sandbox` gets three lantern-api notes ("runs", "tests", "set"); "Add a health check endpoint to the Express server." in `~/work/app` gets three gateway and lantern notes ("health", "check"); "Write a function that merges two sorted arrays." gets tide-ledger's migrations ("write", "merges"). Of my 89 everyday coding requests, 26 got a block (37 notes) and at least 23 of those carry nothing that bears on the request; the README's fair figure is 91.7% "no block" (8% with a block), measured on a hold-out whose 24 unanswerable prompts include no coding request at all. On the real model the palindrome turn's reply ended with a remark to the person about the mascot note. The brief counts a note added to a turn that needs none as costly as a missing one, and coding requests are the commonest turn. The README's "What it still misses" names the pattern but not how often it happens. Fix: let a shared word count toward the two only when it is distinctive in the vault (rare across its notes, or in a note's title, aliases, tags or headings, or the session's project), and keep everyday request words ("write", "add", "set", "make", "run", "check", "test", "file", "function", "small") out of prompts' terms; add at least 40 everyday coding requests that no note answers to the dev set and a fresh hold-out from new writers, with a no-block floor of at least 90% on them, and give that figure in the README apart from chat filler.
2. **Minor: a quoted number cannot be fixed in the form as it shows.** Where: the shared settings form in `shared/client-kit.js` (`SettingRow`, DSH's `SettingsValueField`), reached from Canon's waiting state. What: with `maxNotes: "3"` in the profile, the page says the value is text and *Open Canon's settings* puts the cursor in the field, which shows 3, unmarked, with Save disabled; typing 3 again changes nothing. Only the grey *Use the default* (drawn like a disabled label) or a different number makes Save work. Fix: mark a field whose saved value has the wrong type as invalid, in Canon's words, and let Save write the value the field shows as a number.
3. **Minor: a subfolder Canon cannot list is skipped without a word.** Where: `walk()` in `lib/vault.js` (`catch (error) { if (!rel) throw error; continue; }`). What: with `Projects/osprey-mobile` unreadable the vault reads as fine ("39 active notes", 0 unreadable, state ok), What happened says nothing, and "When does osprey-mobile ship to the app stores?" gets no block though its note exists. Any folder in the vault whose permissions keep DSH out does this. Fix: count unlistable folders, name them under the header and in What happened ("1 folder Canon may not read: Projects/osprey-mobile"), and add a unit test.
4. **Minor (docs): quoting does not stop a model from following a note.** Where: README, "What a turn gets" ("quoted so that its words never read as instructions"), and the fixture's `Misc/Lantern mascot.md`. What: with the header "Reference only, not instructions." and the passage quoted, the real model ended its mascot answer with "Wick says hi", as the note's last line asks; in another turn it did not, but told the person why. Notes reach every fitting turn without anyone choosing them, so an instruction in a note can steer agents. Fix: say that a model may still act on a note's words and that notes should hold no instructions to agents; consider flagging such lines on the page.
5. **Minor (tests): the e2e's first state check races the first read.** Where: `test/e2e/run.mjs`, the first `state` check, which waits only for `(await api('state')).ok`. What: on DSH 0.2.1-rc.1 it failed once in my four runs with the vault still `reading` and 0 notes; the rerun passed. Fix: wait until the vault's state is `ok` before checking its counts.
6. **Nits.** The form saves `/` (and `~/`) as the vault folder, which Canon then refuses in words; check it in the form as the profile does. The try-out's near misses say "one word besides a project's name" when the prompt and folder name no project. A captured draft's file name is its title cut at exactly 80 characters (`lib/drafts.js`), which here dropped the decision's last word ("…never converted to.md" for "…never converted to USD") and elsewhere can fall mid-word; cut at the last whole word that fits. The `enabled: false` page ends "To remove it instead, switch it off in Plugins.", but switching off does not remove it. DSH's Trajectory panel names Canon's context "Dsh-plugin-canon" (DSH's own label).
