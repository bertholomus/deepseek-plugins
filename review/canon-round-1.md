## Findings (most severe first: blocker, major, minor, nit; each with where, what, and the fix)

1. **Major: a vault folder Canon cannot list reads as an empty vault.** Where: `lib/vault.js`: `walk()` rethrows the error from the vault's own folder (`if (!rel) throw error`) outside the `try` in `read()` that turns `realpath` and `stat` errors into `folderProblem`; `refresh()` only logs a warning, so the state is never set. What: with *Vault folder* on a copy of my vault made unreadable (`chmod 000`) the header says "Reading ~/…/vault-locked: 0 active notes and 0 drafts. Read just now.", with no error, no entry in What happened, and *Read again* changes nothing; every turn quietly gets nothing. Moved there from an earlier error, the page kept the earlier folder's words ("…/vault-file.md is a file, not a folder") under the new path. The README promises "A vault folder that is missing, a file, or not readable says so and what to do", and its own Mac case (a vault in Documents or iCloud Drive DSH was not allowed into) fails at this same listing call whenever the folder itself can still be looked up (I did not try a real privacy denial). Fix: catch the listing error of the vault's folder in `read()` and set `{ state: 'error', error: folderProblem(error, display) }` (EACCES and EPERM already have the right words), log it, and add a unit test with an unreadable vault folder.
2. **Major: notes that do not answer fit any prompt that names a project.** Where: the fit rule in `lib/search.js` with the terms of `lib/text.js`. What: `lantern-api` (a tag, a folder, a `project` field) gives two terms, so "the lantern API" shares two words with every lantern note, and a title that names the project ("Lantern mascot", "Lantern on-call") is a strong-field match on its own. "Does the lantern API support websockets?", "Rename the lantern API's logger variable to log." and "Write a unit test for the lantern API's pagination helper." each get 3 notes, none about the question (920 to 940 characters). Real turns: the capture request got Home.md, the queue decision and On-call; "On which weekday do lantern releases go out? One word." got the checklist and the mascot note ("lantern" and "word"). Words about the vault itself do the same: "Answer from the team's shared notes" matches Home.md ("Shared notes for the team's agents"), which came first in the quartz session, above the quartz note. The model ignored the extra notes in every answer, but they cost tokens on every turn and blur "the few active notes that fit". Fix: count a project name's parts as one term for the two-word rule and the floors; ask for at least one prompt word beyond the project's own name; leave words about the vault ("note", "notes", "vault", "canon", "shared", "team") out of prompts; and measure it on a labelled set (below).
3. **Major: the try-out's folder field ignores `~/`.** Where: `client.js` `TryCard` (placeholder `~/Projects/app`) → `remote.search` → `search.js` `folderKeys`, which finds no project in anything that does not start with `/`. What: `~/Projects/dsh-plugin-suite-judge/canon-r1/ws/Projects/quartz-cache` gives no "this project" lift and a different order than the same folder as a full path, so "the exact text the turn gets" is not what a turn there gets, and nothing says the folder was not used; a relative folder is ignored the same way. Fix: expand `~/` to the home folder before the search, and refuse anything else that is not a full path, in words.
4. **Minor: the block's paths read as workspace paths.** Where: `recall.js` `HEADER` and `citation`. What: in the quartz session the real model tried to read `Projects/quartz-cache/Quartz ports.md` in its workspace (FS_NOT_FOUND), globbed and read the README before answering, three wasted steps, then told the person the note "is not present in this session's workspace". Fix: say in the header that the paths are inside the canon vault, not the workspace (or cite them as `canon:Projects/…`).
5. **Minor: a wrong type in the profile stops Canon.** Where: `Config` in `lib/index.js` (`z.number()`, `z.boolean()`, `z.string()`). What: `maxChars: "900"` in the profile: after a restart Plugins shows Canon with only "Problem" and no settings, and Canon's page says "Canon is not running. Open Canon in Plugins and switch it off and on again. If it still does not start, restart DSH.", none of which helps; the same edit while Canon runs is dropped without a word (the old values stay, and a good `maxNotes: 5` in the same edit was dropped with it). The README says "A wrong value never stops Canon from starting". Fix: let the schema take any value with its default and check the types in `checkConfig`, in words, as the ranges are; at least have the not-running page point at the profile row.
6. **Minor: the form saves a promoted-notes folder inside the drafts folder.** Where: the settings form's rule for `promoteFolder`. What: "Drafts/Kept" keeps Save enabled; Canon then refuses the value and waits ("must be outside the drafts folder (Drafts)"). Fix: the same check in the form, with the same words.
7. **Minor: focus is lost after the switches and Promote, and the session switches share one name.** Where: `TurnCard`, `SessionsCard` and `DraftsCard` in `client.js` (the controls are disabled while busy, and a promoted draft's row goes). What: Enter on *Turn off for this session* on the card, Space on a session's switch on the page, and a successful Promote leave focus on the page body; every session's switch is named "Add notes". Fix: keep the control focusable while busy (or put focus back), move focus to the status line after Promote, and name each switch "Add notes to <session title>".
8. **Minor (docs): Read only binds Canon, not the agents.** Where: README, "Drafts and Promote" and "Switching it off". What: with Canon read only and asked to record a decision with "whatever tool you have for saving canon notes; if you have none, just tell me so", the real model found the vault two folders above its workspace with `ls`, read a decision for its format and asked to escalate to full access to write an active note straight into `Decisions/`. I rejected it and nothing changed, but nothing in the README says that Read only covers only Canon's own writes. Fix: say so, and that DSH's sandbox is what keeps agents' own tools out of the vault (under Workspace Write a write outside the workspace asks first, as it did here; under full access nothing asks).
9. **Nits.** Draft previews show raw Markdown cut mid-word ("**Decided 2026-10-17 (Pacific):** … **Impli"); "Shares the words “port”, “servic” and “listen”" shows a stem; refusals mix straight and curly quotes ("Allow promoting drafts" next to “Allow promoting drafts”); "Reading <vault>: …" reads as a read still under way, and says "Read just now" after a read that failed; the read-only drafts line says "Drafts in Drafts."; DSH's Trajectory panel names the source "Dsh-plugin-canon"; What happened's time column has no fixed width, so entries start 4 px apart.
