## Findings (most severe first)

1. **Minor (reliability, UX): after a lost store, `/coordinate` brings the chat back without its threads, and the window disagrees with the plugin in both directions.** Where: the store-unreadable recovery (`lib/projects.js` `onCommand` and start-up), the page's notice and the README's "Its record". What: with the store cut short, the plugin kept it aside and said so (good), but until `/coordinate` the window still drew the chat as coordinating ("2 threads", "New threads …" with nothing after it, **Stop coordinating**) while it had no thread tools (picture 30). The page offers "run /coordinate again in each chat" as a way back: it brought the chat back with an empty thread list, and after a restart the menu read "0 open · No threads yet", the old handback card named its thread "t2", and the session list still nested both threads (picture 41). Only putting the file back while DSH is closed brought the threads back (picture 42). Rare (the save is atomic, so it needs outside damage), but then the owner loses his threads by following the page. Fix: on `/coordinate` (and at start) re-adopt a chat's threads from its own log (the `thread_start` results name each thread's session and title); until then have the menu say the plugin lost its record instead of "…"; and say on the page and in the README that only the kept file brings the threads back otherwise.
2. **Minor (reliability): a thread cut off during its `thread_handback` call gets both its handback and a "cut off without a handback" note.** Where: `lib/projects.js` `readTurn` (`handedBack` needs DSH's `tool/result` for the call, which a crash never writes) and the start-up catch-up. What: in my first 0.2.0-rc.2 run DSH was killed while t1's handback call ran; at the next start the plugin delivered the held handback (`news …/t1 handback done seq=12`, `flush … sent=1`) and then sent `news …/t1 stopped seq=13` and `idle-note …/t1 chars=0 ended=interrupted`, so the chat hears "done" and "ended without a handback, cut off; its card has Resume" about the same thread, the owner gets a "stopped" item for a thread that finished, and a Resume there would send the finished thread on again. Fix: when reading a cut turn, count a handback the store recorded for that thread after the turn began as handed back, and send no idle note or stopped news then; add the case to the crash phase.
3. **Minor (test depth): the crash phase is racy and failed under load.** Where: `plugins/coordinator/test/e2e/run.mjs` line 762: `since(mark, 'coordinator').some((r) => r.fresh.includes('Alpha re-checked the notes.'))` is already true for the chat's own prompt sent at line 761, which carries those words. What: on a loaded Mac DSH was killed before t1's handback reached the chat; at the restart the handback came from the queue with its `E2E:slow 120000` line, the chat's answer took 120 s, the Theta note waited behind it past the 30 s wait, and run.mjs stopped at 69 of 227 checks (with the window test's Preview-Notice "Continue" click timing out as well). Alone it passed 227/0, and the builder's 8:37 PM run passed; this Mac always carries about 20 agents. Fix: wait for the handback itself (`[Handback from thread t1` in a chat request, or the log's `handback …/t1 … delivered`), give the notice handler a longer timeout, and run the e2e once with a second DSH up before handing over.
4. **Minor (usefulness): threads share one folder, and a thread's shell-only edits are never listed in its Changes.** Where: README "Not yet"; `lib/projects.js` `shellEdits`, `lib/changes.js`. What: two threads that edit one file at once collide; DSH's own "Edited N files" card shows other threads' edits; a file a thread changed only with a shell command shows in its counts but not in its Changes tab ("aren't shown yet", picture 11), and in a window another session shares it counts only what its own commands alone could have written (my run: `shell-window … shared kept=0/1`). The owner's goal names per-thread changes and the stack runs many sessions in parallel, so he will meet this. Fix: an opt-in git worktree per thread for repositories (with the Changes tab diffing the worktree), and list shell-changed files in the Changes tab from the snapshot diff.
5. **Nit (guards):** missed plausible commands: `bun -e "await fetch(…, {method:'POST'})"` (Node and Deno are caught), `curl -K cfg.txt …` (a config file can carry `-X POST`; can't tell, so it should ask) and `$(which curl) -X POST …`; deletes: `trash calc.py`, `git stash -u` (takes untracked files out of the folder) and `git branch -D`. Where: `lib/sends.js` (the code runtimes, curl's flags), `lib/deletes.js`. Fix: add Bun beside Node and Deno, treat `-K`/`--config` as can't-tell, and count `trash` and `git stash -u`/`--include-untracked`/`--all` as deletes of what they take; list `git branch -D` in the README's "Not yet" if it stays out.
6. **Nit:** the plugin's page and Thread settings still name config keys ("List your personal and infrastructure tools under guardedTools in this plugin's config", picture 17), round 1's nit 9.
7. **Nit:** `config-fixed` is not logged when the save that fixes a live key also changes a key that restarts the plugin: my log has six `config-problem` lines and nothing saying they were put right.
8. **Nit (docs):** the README is now 400 lines and 77 KB (69 KB in round 1). The "At a glance" list helps; the long behaviour sections could move to a second file linked from it.

## Round 1's findings

1. Held handback read "No handback yet" after `/coordinate off`, "Its 5 threads keep running": **fixed** (the window e2e on every build: "its row reads 'Done · held until you coordinate again'", "/coordinate off says how many threads stay open and how many run"; I did not repeat it by hand).
2. A handback whose answering turn DSH cut off was never raised again: **fixed** (the crash phase on every build, incl. my 0.2.0-rc.2 rerun, logs `raise-cut` and checks it is sent once, saying why); a new edge in the same area is Finding 2.
3. An unreadable store silently replaced: **fixed** (kept aside byte for byte, mode 600, logged, named on the page; failed saves logged once and tested in the host suite); what remains is Finding 1.
4. The delete prompt cut the path before the file name: **fixed** (paths from the thread's folder, real path too; long paths cut in the middle, keeping the name).
5. The chat not told how the owner answered a thread's prompt: **fixed** (run.mjs checks the roster's "allowed" and "declined" lines in a real DSH on every build; not repeated by hand, no model turns).
6. `mv` out of the folder not a delete: **fixed** (`mv`, `mv -t`, `xargs mv`, `rsync --remove-source-files`; `truncate -s 0`, `cp /dev/null` and `sed -i` are listed under "Not yet").
7. Shell edits dropped whenever another thread worked in the same window: **partly fixed** (it keeps the files only its own commands could have written; no per-thread folders: Finding 4).
8. Switched off, dead thread tabs: **partly fixed** (the chat on screen's tabs close, window e2e on every build; another chat's open thread tab still shows DSH's placeholder, which a plugin can't reach, and the README says so).
9. Config keys and thread ids in the UI: **partly fixed** (threads by title in Thread settings; the page still names `guardedTools`: Finding 6).
10. The log couldn't tell pause from resume; a wrong live setting not logged: **fixed** (values in `settings` lines; `config-problem threadEffort` logged for a live key), with Finding 7 left.
11. Contrast unmeasured, no Wallpaper pictures, no reduced-transparency rule: **partly fixed** (contrast measured on every build, the rule added; Wallpaper still not in the builder's tests; I checked it by hand and it reads well).
12. README length: **partly fixed** (an overview and short sections, but longer: Finding 8).
