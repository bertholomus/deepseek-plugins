## Findings (most severe first: blocker, major, minor, nit; each with where, what, and the fix)

No blockers and no majors.

1. **Minor (reliability, docs): a refused `POST /sessions` still makes a workspace.** `lib/api.js` `createSession()` calls `workspaceFor(body)`, which calls `workspaces().create(full)`, before `checkModel()` and before `sc().create()` (where DSH checks `agentPreset`). Seen in DSH Test: a model, a provider and an effort one step off, each with a folder DSH did not know, were each refused 400 with no session, but `GET /workspaces` went from 2 to 5 and the window's sidebar shows the empty workspaces (picture); an unknown `agentPreset` is a 409 after its workspace is made. The README says `POST /sessions` "checks everything before it makes anything". Fix: check the folder with `stat` only and find it in `workspaces().list()` by real path; check the model and the agent preset (a 400 naming DSH's presets) first; call `workspaces().create(full)` just before `sc().create()`; add an e2e check with a new folder: after a refused create, `GET /workspaces` is unchanged.
2. **Minor (test depth): the committed e2e fails on DSH 0.2.0-rc.2.** In both of my runs the step "its Plugins page says whether it serves…" timed out clicking Plugins (`test/e2e/run.mjs` line 639): DSH 0.2.0-rc.2's Preview Notice arrives after `openWindow`'s calm wait and covers the button; the step clicks once with no notice handling (the session step before it already retries). 11 Plugins-page checks did not run, and the hand-over's "118/118 on 0.2.0-rc.2" did not reproduce. With `dismissNotices(page)` and a retry before that click, 118 of 118 pass. Fix: that retry (or close the notice in `openWindow` until none has come for longer), then run each build three times.
3. **Minor (reliability): a refused `socketPath` still gets its log folder.** `lib/config.js` defaults `logFile` to `bridge.log` beside `socketPath` even when that path has a problem or is refused, and `lib/log.js` makes its folder. Seen: a 144-byte `socketPath` under `~` was refused in words, and the bridge made a new folder in the home folder to hold `bridge.log`; with another process's socket the refusal went into `bridge.log` in that process's folder (a mistyped live path would write into the live DSH's bridge log); with a 755 folder the log went into it. Fix: while `socketPath` has a problem or is refused, write to the default `<DSH home>/hermes-bridge/bridge.log` (unless a valid `logFile` is set), and never make folders for a refused path.
4. **Nit (reliability): a repeated terminal id.** `POST /sessions/:id/terminals` with the id of a running terminal answers 200 (DSH hands back the existing one), types `command` into that shell, and `lib/terminals.js` `create()` replaces the bridge's state for it: the output kept so far is dropped (seen: `firstSeq` 2 after the re-create) and the old attachment and `retain` hold are not closed (from the code). `dshb` sends no id, so only direct API users meet it. Fix: when `tc.list(sid)` already has the id, answer 409 `terminal/exists` (or reuse the state without re-attaching).
5. **Nit (usefulness, docs): `nextStep` counts DSH's own notices.** After an access change, DSH queues "The approval policy changed from "never" to "ask" (changed by the user)." as a next-step inbox item (`source.kind: "user-approval"`), so an idle session reads `pending.nextStep: 1` with no steer waiting, and the window shows nothing waiting. Fix: count only messages a person or client wrote (or report DSH's notices apart), and say so where the README defines `nextStep`.
6. **Nit (UX, screen readers): value and mark run together.** In "Settings in effect" the mark sits in its own span with only a CSS margin (`lib/client.js` `.dshhb-mark`), so the accessible text is "truedefault", "1048576default", `"lots"not valid`. Fix: a text space, or "(default)".
7. **Nit (docs, API edges).** On these DSH builds there is no Auto preset, so `access: "auto"` is a 400, not the README's 403. An effort without a model is now a 400 (`dshb new --effort max` without `--model` used to make the session and drop the effort); "From 0.1 to 0.2" does not say so; giving the effort to DSH's default model (the catalog names it) would be kinder. "Even two DSHs starting at the same moment cannot take each other's socket" holds with no old socket there; with a stale one, both can pass `socketAnswers()` and the second's `unlinkSync` can remove the first's new socket (`lib/socket.js`, a small window, from the code). A mistyped setting name is ignored without a word. Fix: README words; move the stale socket to a private name and check its inode before removing it; name unknown keys in the log and on the page.
8. **Nit (UX words).** The reason lines on the Plugins page give full paths (`/Users/<you>/…`) while the facts beside them use `~/`; "Since 8:15 PM" carries no date once a day has passed. Fix: tildify in `describe()`; add the date when it is not today.
