## Findings (most severe first)

No blocker and no major finding.

1. **Minor (words): the 404 `request/not-found` does not say what to do next.** Where: `lib/bridge.js` `requestPage` (line 1046) and the README's "What became of a prompt" (line 93). What: when DSH quits within a moment of taking a prompt, nothing of it reaches the disk; after the start, a caller that asks first (as the README's own loop does) gets "has no message with request id …: none is in its log, and the bridge sent none to it since DSH started", with no next step. Fix: add "If you sent it before DSH started, it did not arrive: send it again with the same request id." to the message, and the same line under the states table.
2. **Nit: the bridge remembers a request id for one session only.** Where: `remember` and `sentAttempt` (`lib/bridge.js` lines 706 to 716): `SENT` is keyed by the request id alone. What: if a caller uses one id for two sessions, the send to the second makes the bridge forget the first one's send while it is still on its way (milliseconds, or up to 60 s after a 504): a retry to the first inside that window is sent again, and its `GET …/requests/<id>` is a 404. Fix: key `SENT` by session and id (`${sessionId}\u0000${requestId}`), or say in the README that a request id belongs to one session.
3. **Nit: `seq` of a prompt can move.** Where: `attemptState` (`lib/bridge.js` lines 352 to 405). What: while a turn has taken the prompt but DSH has not saved it as a message yet, `read` carries the queue event's `seq` (7 in my restart test); once saved, the message's (10). The README does not say what `seq` is. Fix: give `seq` only for the saved message (and the queue's in `queued`), or say "the newest event the state was read from".
4. **Nit: "DSH's logger says it once" is a line the owner cannot see.** Where: README line 14. What: DSH keeps plugin log lines in memory (the settings paragraph says so; the e2e cannot see it either), so for an unwritable log `GET /health` is the only place it shows. Fix: word it as line 38 does ("which may keep it in memory only: read `GET /health`").
5. **Nit (DSH's limit, not scored down): a failed start reads "Problem" with no reason in the window.** DSH's plugin inventory carries only `fiberPhase` to the page (no reason field, and DSH has no host-side notice for plugins), so the plugin cannot put it there; the README, the start error and the bridge's log name the reason and the way back. Keep it as it is unless DSH adds a place.
6. **Idea (scope, not scored down):** an unattended turn under Workspace Write that waits for an approval or a question reads `read` until someone answers in the window, and nothing in `requests/<id>` says why. A `waitingFor` hint read from the session's projections, or a README line on watching the approval events, would save a cron job from timing out blind.
