## Findings (most severe first: blocker, major, minor, nit; each with where, what, and the fix)

No blockers and no majors.

1. **Minor (docs, UX): a read takes the person's terminal.** `lib/terminals.js` `state()` attaches on the first `GET …/output` for a terminal the bridge holds no attachment to, and DSH 0.2.1's attach gives the newest attachment "exclusive input control" (`dsh-api-terminal-controller`). So an agent that only looks at the owner's shared terminal makes the owner's tab read-only, before it types anything. The README says "Input from the bridge takes input control" and the e2e checks read-only only after input. Fix: README (Terminals, Limits): "the bridge's first read or input on a terminal takes input control; after you take it back, the bridge keeps reading without taking it, and only its next input takes it"; add the read-only-after-a-read check to the e2e so the words stay true. (A real observer mode needs DSH; `retain` holds a terminal without control but gives no output.)
2. **Minor (UX, DESIGN 6 and 9): the icon disappears in dark.** `icon.svg` strokes with `currentColor`, which DSH's Plugins page renders black in both themes (measured in the picture): 1.15:1 on DSH's dark ground (#151517), against DESIGN's 3:1 for icons in both themes. Fix: fixed colours that pass on #fff and #151517, as the suite's other icons do (their blue gradients), and a picture of the Plugins page in both themes in the e2e.
3. **Minor (UX): the window never says the bridge is not serving.** With a wrong setting, a socket another process holds, or an open folder, the bridge rightly keeps the socket closed and says why in `bridge.log`, but DSH's Plugins page shows a green Running, and the settings are not on the page at all (`Config` is `z.any()` by design). The owner learns it from a failing Hermes job. Fix: show one line on the plugin's page (`plugins.bundle.config`): "Serving on this DSH's socket" or "Not serving: maxBodyBytes must be a whole number of bytes from 1024 to 67108864", with the setting to change.
4. **Minor (reliability, docs): a model typo makes a session.** `lib/api.js` `createSession()` checks only that provider and model are text, then makes the session and only then asks DSH to choose the model: `No-Such-Model` or an effort the model does not take gives 409 "session … was made, but choosing its model failed" and leaves a blank session in the owner's list each time. The README's "checks everything before it makes anything" reads as if this cannot happen. Fix: check provider, model and effort against `sc().modelCatalog()` (already used by `GET /models`) before `create`, as a 400 that names the models; keep the after-create path for real DSH refusals.
5. **Minor (usefulness): a waiting followup is invisible.** After `cancel`, DSH keeps a queued followup in the session's inbox and runs it only with the next prompt (seen with the real model; the window shows it above the composer). `GET /sessions/:id` says `idle` with no sign of it, so `dshb wait` returns while the agent's message still waits. Fix: add `pending: { nextTurn, nextStep }` (counts from DSH's inbox projection, which `GET /sessions` already returns) to `GET /sessions/:id`, and say in the README what a cancel does to queued messages.
6. **Minor (reliability, docs): terminal sequence numbers restart.** When the bridge restarts (row change, off and on, window switch) and re-attaches, `seq` starts again at 0 (seen: 3, then 0). A client polling with its old `after` gets nothing until the new count passes it, and nothing tells it the numbers restarted. Fix: send an epoch with `seq` (for example `health.since` or an attachment id in every output answer), or keep the numbering going past a restart, and say it in the README.
7. **Nit (docs, API): statuses differ from the README.** A wrong method on `/health`, `/workspaces` or `/` is 404 "no endpoint", not 405; `GET /sessions/<unknown>/terminals` is 200 `[]`, not 404; `provider` without `model` is silently ignored in `POST /sessions`; `attached` stays `true` for a terminal whose shell exited; `openTerminals` counts the terminals the bridge holds, not the session's. Fix: 405 with the right method for every known path, 404 for an unknown session's terminals, 400 for a provider without a model, and one word in the README for `openTerminals`.
8. **Nit (docs): what shows in the window.** A session made with a title and no first message is listed by DSH as "New Session" until its first message (DSH's own rule; the bridge's `title` is right). README "(DSH's plugin log gets the same line)": DSH 0.2 keeps those lines in memory only (the HANDOFF says so), so the bridge's log is the only place to read them. Fix: say both in the README.
9. **Nit (code read, not reproduced): two first touches at once.** In `state()`, two requests for a terminal the bridge does not hold yet both pass `await agentOf()` and each makes and attaches its own state; the first is dropped from the map but its attachment and `retain` hold stay open until the shell ends, and `closeAll()` cannot reach them. Fix: keep one pending promise per key and await it. Also: terminal titles with control characters reach DSH as given; refuse them like other bad text.
