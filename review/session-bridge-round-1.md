## Findings (most severe first)

1. **Major: a retried create sends the job twice.** Where: `lib/bridge.js` `createSession` (lines 523 to 545): `requestIdOf(body)` checks the id's form, but nothing looks it up; README line 7 ("a retry with the same request id is never sent twice"), line 91, and the example at line 120, which is exactly this call. What: on the real instance at 10:44 AM, I posted the same `{workspacePath, title, text, requestId: "j1-create-retry-1"}` twice. I got two sessions (`session-28bba03d…`, `session-4d8ba9fd…`), both `accepted` without `alreadySent`, and both read the prompt (state `read`, turn 1; the text is on disk in both). A cron job that retries a create after a timeout runs its job twice. The stand-in showed the same. Fix: remember request id → session id for creates (alongside `SENT`), and answer a repeat with the existing session and `prompt.alreadySent: true`. To survive a restart, also look in the workspace's sessions for a `user/message` with that `rpcId`. Add a unit test, and an e2e check that the same create twice gives one session and one message.
2. **Major: after a restart under a running turn, the prompt can never be resent with its id, though the README says it can.** Where: `requestState` (`lib/bridge.js` 232 to 282) and the `alreadySent` branch of `prompt` (line 459); README lines 7, 87 and 91. What: with the real model, DSH saved the user message when the step started (seq 10). After a forced restart the turn ended `interrupted`. `GET …/requests/j1-restart-oy2esp` then said `answered`, `end.kind: "interrupted"`, `reply: null`, and both resends with the same id came back `alreadySent: true, state: "answered"`, so the job was never done. The README's restart story covers only `dropped`. The e2e restart check uses a scripted slow model that stops before the message is saved, so it reaches only `dropped` and passes. Fix: give this case its own state (for example `interrupted`), or `answered` with `resend: true`, when the turn that read the message ended interrupted or in error with no reply. Then let a resend with the same id go through (the bridge can send it under a derived `rpcId` and map it back), or document plainly "send it again with a new request id". Add an e2e case whose scripted model saves the message and then hangs before the restart.
3. **Minor: the 504 at 60 s for a prompt is not kept.** Where: `lib/bridge.js` line 467 hands `AbortSignal.timeout(PROMPT_MS)` to DSH, which checks the signal only when the call starts; README line 108. What: a stand-in DSH that held the prompt for 70 s got `200` after 70 s, not a 504 at 60 s. A script that trusts the README's deadline can hang longer than it planned. Fix: race the call against a timer and answer 504 with "DSH may still take it: ask GET /sessions/:id/requests/<id>", or change the README.
4. **Minor: every read failure is reported as "session not found".** Where: `lib/bridge.js` line 429. What: an `EIO` from DSH's read became `404 session/not-found` (stand-in). A script told "not found" may make a new session and send its job again. Fix: map only DSH's not-found error to 404, and answer anything else with 500 (or 503) in words.
5. **Minor (UX): the Plugins page shows an id and jargon, and a bridge that cannot listen reads "Running".** Where: the plugin has no `locale/en.json` `meta` and no icon (other suite plugins have both); `lib/index.js`. DESIGN.md §9, "Words": a title, one plain sentence and a 36 by 36 SVG; no ids where people read. §9, "States": failed never reads as running or idle. What: see the plugins and refused pictures. With the socket refused, the window says "Running". The README's "hands the same words to DSH's logger" left no line in any file of the instance, so only the bridge's own log says why. Fix: add `meta` (title "Session Bridge" and a plain sentence such as "Lets scripts and scheduled jobs start, prompt and read DSH sessions on this Mac") and an icon. When the bridge cannot listen, show it as failed with the reason on its row (or raise one DSH notice), not "Running".
6. **Minor: `reasoningEffort` without a model is dropped silently.** Where: `createSession` runs `selectModel` only `if (body.model)` (line 539); its type check (line 524) leaves out `reasoningEffort`. What: `POST /sessions` with `reasoningEffort: "max"` and no model gave 200 and the effort was not applied; `reasoningEffort: 7` also gave 200. Fix: refuse in words ("reasoningEffort goes with provider and model"), or apply it to DSH's default model; check its type as `POST …/model` does (line 480).
7. **Minor: a queued prompt removed from DSH's queue reads `read`, and its retry is refused.** Where: the inbox replay in `requestState` ignores the splice's `outcome` (`canceled` when the owner removes it). What: in the stand-in, a followup removed while a turn ran read `read`, and a retry was refused with `alreadySent: true`, so it was never sent. Fix: treat a removal whose outcome is `canceled` as `dropped` (or a new `discarded` state) at once.
8. **Minor: the shared-folder guard misses the home folder spelt another way.** Where: `lib/bridge.js` line 856 compares `resolve(dir)` with `resolve(homedir())` as strings. What: in the stand-in (temp folders standing in for home), a socket folder that was the home folder in another letter case (the disk ignores case), or reached through a symlink, passed the guard, and the bridge set it to mode 700. Fix: compare `st.dev` and `st.ino` with `statSync(homedir())`. Better still, only close a folder the bridge made itself.
9. **Nit: a wake-up can be lost.** `waitUntil` (lines 371 to 417) does not run its check after it registers, though its comment says "Run `check` now". An event that lands between the route's first read and the registration waits until the next event or the deadline. Then the answer is `timedOut: true` with a stale state (stand-in: 5 s wait, 0 events). Fix: `void run()` right after `waiters.get(sessionId).add(wake)`.
10. **Nit: the README's wait wording.** A wait ended because the bridge stopped says `timedOut: true` (say `stopped: true`). When DSH itself quits, a wait in flight gets a hang-up, not an answer ("stopping the bridge answers every wait at once" holds for settings changes and switch-off). With the bridge off the socket file is gone, so scripts get "no such file", not the "connection refused" the README names.
11. **Nit: the log.** Rollover compares characters, not bytes (`logSize + text.length`, line 342). `statSync`, `chmodSync` and `appendFileSync` follow a symlink at the log path. Request ids are written as given, so the README could say not to put secrets in them.
12. **Nit (tests): delivery is proven through the bridge itself.** The e2e "in its log" checks read events through the bridge's own `events` route. The harness's `savedEvents` (the log on disk) is unused. Check at least one delivery against the saved log, as I did by hand.

## What would make it a 9.5

- Creates that are safe to retry: one session and one message per request id, across restarts too (finding 1), with tests.
- A restart story that holds with a real model: a distinct state for a prompt whose turn was cut off after DSH saved it, and a way to resend it, safely and once (finding 2), with an e2e case that reaches that path.
- Keep the documented deadlines, or document what really happens; report read errors as what they are (findings 3 and 4).
- Present the plugin as DSH presents its own (title, plain sentence, icon), and show a refused bridge as failed with its reason in the window (finding 5).
- Close the small gaps: `reasoningEffort` alone, a discarded queued prompt, the home guard by device and inode, the lost wake-up (findings 6 to 9).
- Bring the README in line on all of the above: "never sent twice", restarts, the 504s, what a wait gets when DSH quits, "no such file" when off.
